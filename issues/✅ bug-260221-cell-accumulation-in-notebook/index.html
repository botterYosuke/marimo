    Issue: プレイ中に追加したセルが backcast.py に永続保存され次回起動時に誤発火する¶

    報告日: 2026-02-21 重要度: P2 状態: ✅ 修正済み

    症状¶

    ゲームプレイ中にユーザーが作成した新規セル（bt.buy()、bt.chart("7203") 等）が backcast.py に永続保存される。次回起動時にこれらのセルが自動実行（auto-execute）され、スキルが意図せず発火する。

    プレイ後に backcast.py が 7+ セルに膨張していることが確認された（本来は 2〜3 セル: setup + markdown + chart のみ）。

    再現手順¶

    1. backcast.py をマリモで開く（初期状態: 2〜3 セル）
    2. ゲームをプレイし、新規セル（bt.buy()、bt.sell() など）を追加する
    3. マリモを終了する
    4. 再び backcast.py を開く
    5. 前のセッションで追加したセルが残ったまま自動実行される
    6. [SkillHandler] Received skill event: BRIDGE_001 等がコンソールに出力され、スキルが意図せず発火する

    確認された蓄積セル（2026-02-21 プレイ後）¶

    セル 内容 問題
    cell-4 前回テストセッション由来の BRIDGE_001 イベント直接発火コード スキルを意図せず発火
    cell-5 bt.buy() — 前回セッション由来 自動実行で誤購入・誤スキル発火
    cell-6 bt.chart("7203") 重複チャート
    cell-7 bt.chart("7203") 重複チャート

    原因分析¶

    marimo はノートブックファイルへの変更をリアルタイムで永続化する設計であり、ユーザーがセルを追加すると即座に .py ファイルに書き込まれる。

    ゲームモードの backcast.py はプレイヤーが自由にセルを追加することを想定して設計されているが、以下の問題がある:

    1. セッションをまたいだセルの蓄積: ゲームリセット（window.__testResetProgress()）はスキル進捗のみをリセットし、ノートブックのセル構成をリセットしない
    2. auto-execute によるスキル誤発火: マリモは起動時にすべてのセルを実行するため、前回セッションのスキル発火コードが再実行される
    3. インタラクティブなノートブックとゲーム状態のミスマッチ: ゲームの「状態」はスキル進捗 JSON に保存されているが、「操作履歴」はノートブックのセルとして永続化されてしまう

    影響範囲¶

    • ゲームプレイの整合性: スキルが意図せず発火し、プレイヤーの実際の操作に関係なくスキルツリーが進む
    • ゲームの公平性: チュートリアルスキルを「習得した」とみなされるが、プレイヤーは実際には操作していない
    • E2E テストへの影響: テスト実行中に蓄積されたセルが他のテストセッションに影響する可能性
    • 開発者体験: デバッグ目的で追加したセル（直接イベント発火コード等）が本番ゲームファイルに残り続ける

    対応案¶

    案1: ゲームリセット時にノートブックをテンプレートに戻す（推奨）¶

    window.__testResetProgress() または専用のゲームリセット機能で、backcast.py を初期テンプレートに書き戻す。

    # game_setup.py に追加
def reset_notebook():
    """ノートブックを初期状態に戻す"""
    import shutil
    template_path = Path(__file__).parent / "backcast_template.py"
    notebook_path = Path(__file__).parent / "backcast.py"
    shutil.copy(template_path, notebook_path)

    案2: 「安全なセル」と「プレイヤーセル」を分離する¶

    初期セル（setup, markdown）を # GAME_CORE コメントでマークし、リセット時にそれ以外のセルを削除する。

    案3: ゲームリセット時の警告表示¶

    リセット操作時に「手動で追加したセルを削除してください」という警告を表示し、プレイヤーに手動クリーンアップを促す。

    案4: .backcast.progress.json にセル状態を含める¶

    スキル進捗に加えて「許可されたセルリスト」を管理し、起動時に余分なセルを検出して警告する。
