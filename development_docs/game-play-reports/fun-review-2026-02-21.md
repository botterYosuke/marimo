## 良い点

1. **コアゲームループの完全動作確認**: E2E テストで SANDBOX_001→006→BRIDGE_001→003 の 9 スキルが自動取得できることが証明された。`bt.chart()` → `bt.buy()` → `bt.step()` → `bt.sell()` → `bt.reveal_data()` → `bt.get_stock_daily()` の全アクションが正しくスキルイベントを発火し、フロントエンド側で completed ステータスに更新される。これはゲームの中核品質として高く評価できる。

2. **TradingViewチャートの没入感**: 本格的なローソク足チャートがゲーム起動直後から表示され、視覚的な第一印象が非常に良い。投資ゲームとしての「本物らしさ」を演出している。

3. **スキルツリーのビジュアル設計**: React Flow を使用したグラフ表示は、スキルの依存関係が一目で把握でき、「次に何をすべきか」が視覚的に理解しやすい。カテゴリ別の左ボーダーカラーコーディング（緑=sandbox、青=bridge、赤=fail など）も直感的。ホバー時にエッジが金色でハイライトされる演出（`skill-tree-graph.tsx:86`）は前提条件の視認性を高めており、関連エッジの opacity 低下（`opacity: 0.3`）による非関連要素の視覚的除外も優れた UX 設計である。

4. **game_setup.py のユーザーフレンドリーな API**: `bt.buy()` 後に `mo.callout` で「**買い注文を出しました** — 7203 @ ¥X,XXX」を返す設計、`_format_step_summary()` による日付・資産・含み損益の整形表示など、Python コードの出力が学習者にとって親切。ガード節（ポジションなしで sell()、データなしで buy() を試みた場合の `mo.callout` 警告）も適切に実装されている。

5. **失敗スキルの設計哲学**: FAIL_001（含み損）・FAIL_002（損切り）・FAIL_003（破産）を「報酬対象」として設計しているのは、投資教育として優れた発想。「損切りはプロの証」「破産も大切な経験」のメッセージと helpContent の投資格言（「損小利大」など）が心理的安全性を高めている。

6. **HUD のリアルタイム更新**: ステータスバーに Time / Progress / Equity / Cash / Position / Trades が揃っており、BroadcastChannel を使ったリアルタイム更新は技術的に適切。Equity に `rewardCash` を加算する設計（`backtest-hud.tsx:117`）は、ゲーム内報酬とバックテスト資産を統合表示するユニークな演出。

7. **トースト通知のクリック連携**: `skill-reward-toast.tsx` のトーストをクリックするとスキルツリーダイアログが自動で開く設計は、「スキル取得 → ツリーを確認したい」という自然な行動フローに沿っていて優秀。

8. **helpContent の段階的開示**: 主要スキルには `helpContent` が設定されており、実際のコード例が丁寧に解説されている。「ノートブックに挿入」ボタン（unlocked 状態のみ表示）でコードを直接入力できる仕組みは、コード入力の摩擦を大幅に削減する。

9. **_check_graduations() による自動卒業スキル**: SANDBOX_001〜005 全完了で SANDBOX_006 が自動発火、BRIDGE_001 AND BRIDGE_002 完了で BRIDGE_003 が自動発火する仕組みは、プレイヤーに「自動で報酬が届いた」驚きをもたらし、良い演出になっている（ただし BRIDGE_003 の前提条件バグは改善必要、改善点 3 参照）。

10. **報酬の数値設計**: 全スキル完了時に初期資金込みで約 289 万円に到達する設計は、「いつのまにか大きな資産を積み上げた」達成感を演出する。マイルストーン総計 135 万円は、スキル報酬総計（約 140 万円）に匹敵する規模であり、報酬の二重構造として機能している。

## 改善すべき点

1. **再接続時スキルイベント消失（P1バグ）**: ページ再接続のたびに進捗がリセットされるため、ゲームとして最も基本的な「達成感の積み重ね」が機能しない。Jotai atom が非永続化のため、再接続時に atom がリセットされた後にスキルイベントが届いても無視される。

2. **guard-validation 3件全 FAIL — ガード警告が E2E で検出不能**: `game_setup.py:85-95` にはデータなし・ポジションなしのガードと `mo.callout` 警告が実装されているが、E2E テスト（`guard-validation.spec.ts`）では3件全てが失敗。グリッドレイアウトでのセル追加・実行フローで `mo.output.append()` の出力が期待するタイミング・場所に表示されない可能性がある。初心者のオンボーディングに直接影響する重大な UX 問題。

3. **BRIDGE_003 前提条件バグ（Python 側）**: `skill_events.py` の `_check_graduations()` で BRIDGE_003 の卒業チェックが `if "BRIDGE_002" in s:` のみであり、BRIDGE_001 の確認が欠落している。フロントエンドの `skill-data.ts` でも BRIDGE_003 の prerequisites に BRIDGE_002 のみが設定されており、Python 側とフロントエンド側で前提条件定義が不整合。

4. **helpContent の `<pre>` レンダリング問題**: `skill-detail-panel.tsx` では helpContent が `<pre className="whitespace-pre-wrap font-sans text-xs">` でレンダリングされており、Markdown として表示されない。`skill-data.ts` の helpContent は `## ようこそ`、`**太字**`、コードブロックなど Markdown 記法で書かれているが、見出し・強調・コードブロックのいずれも描画されずプレーンテキストになる。

5. **HUD の Cash 表示に rewardCash を二重加算**: `backtest-hud.tsx:118,124` で Equity と Cash の両方に同じ `rewardCash` を加算している。「Equity = Cash + 株式評価額」という等式がプレイヤーの期待に反して崩れ、数字の整合性が取れない。

6. **マイルストーン 35→50 の間隔が長すぎる**: 35スキル（米国株ETF）から次のマイルストーン（50スキル）まで 15 スキルの空白があり、難易度 3 スキルが多いフルモード中盤で達成感が得られない長い空白期間となる。

7. **59スキルコンプリート演出の欠如**: 全59スキルに対してマイルストーンは58スキル到達（`skill-data.ts:956`）に設定されており、最後の1スキルを取得しても何の報酬もない。`strategy_templates` のアンロックが設定されているが実際の機能が見当たらない。「やり遂げた感」を生む全コンプリート演出が欠如している。

8. **helpContent の未設定スキルが多い**: SANDBOX_006、SETUP_001〜005 全部、DATA_001・004・005・006、SET_001〜003、TRADE_001〜007・009・010、CHART_001〜002、IND_002・004・006〜009、RISK_001〜010 など多数のスキルに helpContent がない。特に「次のトラックへの扉」である SANDBOX_006「サンドボックス卒業」にヘルプがないことは、遷移点でのプレイヤー迷子を招く。

9. **FAIL_002 損切りスキルの判定タイミング誤り**: `sell()` 呼び出し時点では `closed_trades` にまだ売り注文が反映されていないため、「今回の損切り」ではなく「過去の損切り」を誤検出する。`step()` 内での決済後判定に変更が必要。

10. **セル蓄積によるゲーム状態汚染**: プレイ中に作成したセルがノートブックに永続保存され、次回起動時に意図せずスキルが発火する。「ゲームリセット」の概念が欠如している。

## 具体的な改善提案（優先度順）

### 提案 1: 再接続時スキル進捗の永続化

- **現状**: Jotai atom は非永続化のため、ページ再読み込み・再接続のたびに進捗が 0 にリセットされる。スキルイベントは BroadcastChannel で届くが、atom がリセット済みのため無視される。
- **改善案**: スキル進捗を `localStorage` に保存し、atom の初期化時に `localStorage` から復元する（`atomWithStorage` への移行）。または `initProgressFromFileAtom` のバックエンド側読み込みを再接続後も確実に実行されるよう修正する。
- **期待効果**: プレイヤーの達成感が積み重なり、ゲームとして最低限機能するようになる。リプレイアビリティが大幅向上。
- **実装難易度**: 中（`atomWithStorage` への変更、または永続化フックの追加）

### 提案 2: guard-validation E2E の修正（テストまたは実装の調整）

- **現状**: `game_setup.py:85-95` のガード警告は実装済みだが、E2E テスト `guard-validation.spec.ts` 3件全てが FAIL。`.cm-content` クリック後の `mo.callout` 出力検出ができていない。
- **改善案**: テスト側のセレクターとタイムアウトを調整し、`backcast.py` 実際の警告テキストと spec のマッチパターンを照合する。`mo.callout` の出力がグリッドレイアウト内で正しい DOM 位置に表示されるか確認。
- **期待効果**: 初心者が誤操作時に適切なフィードバックを受け取れることが保証され、オンボーディング品質が向上する。
- **実装難易度**: 低〜中（テスト側の調整のみで解決できる可能性が高い）

### 提案 3: BRIDGE_003 前提条件の修正（Python + TypeScript 両方）

- **現状**: `skill_events.py` の `_check_graduations()` で BRIDGE_003 の卒業チェックが `if "BRIDGE_002" in s:` のみ（BRIDGE_001 確認なし）。`skill-data.ts` の BRIDGE_003 prerequisites も BRIDGE_002 のみ記載。
- **改善案**: `skill_events.py` を `if "BRIDGE_001" in s and "BRIDGE_002" in s:` に修正。`skill-data.ts` の BRIDGE_003 prerequisites に `"BRIDGE_001"` を追加。長期的には前提条件の「唯一の真実」をどちらかに置き、自動生成するアーキテクチャへ移行する。
- **期待効果**: スキルの前提条件がゲームデザインの意図通りに機能し、順序スキップによる不正卒業が防止される。
- **実装難易度**: 低（2ファイルの1行修正のみ）

### 提案 4: helpContent の Markdown レンダリング修正

- **現状**: `skill-detail-panel.tsx` の helpContent 表示が `<pre>` タグを使用しており、Markdown 記法（見出し `##`、太字 `**`、コードブロック ` ``` `）がプレーンテキストとして表示される。`skill-data.ts` の helpContent は全て Markdown 記法で書かれているため、意図した表示とのギャップが大きい。
- **改善案**: `<pre>` を `react-markdown` コンポーネントに変更する（または既に使用中の `mo.md()` 相当のレンダラーを流用する）。シンタックスハイライトには `react-syntax-highlighter` を組み合わせると Python コードが読みやすくなる。
- **期待効果**: helpContent のコード例が見やすくなり、プレイヤーが「ノートブックに挿入」ボタンを使うモチベーションが高まる。
- **実装難易度**: 低（`react-markdown` パッケージは frontend に存在する可能性が高い。差し替えのみ）

### 提案 5: HUD の Cash/Equity 加算ロジック整理

- **現状**: `backtest-hud.tsx:118,124` で Equity と Cash の両方に同じ `rewardCash` を加算している。「Equity = Cash + 株式評価額」の等式が崩れ、プレイヤーが数字の関係を理解できない。
- **改善案**: `rewardCash` は Equity のみに加算し、Cash はバックテストの純現金残高をそのまま表示する。または HUD に「スキル報酬」を別アイテムとして独立表示し、加算せずに区別する。
- **期待効果**: HUD の数字の整合性が取れ、投資学習として「現金残高と資産の違い」を正しく学べる。
- **実装難易度**: 低（`backtest-hud.tsx` の1行変更）

### 提案 6: マイルストーン 35〜50 の間のサブマイルストーン追加

- **現状**: 35スキル（米国株ETF獲得）から 50スキル（Backcastエキスパート）まで 15 スキルの空白があり、難易度 3 のスキルが多いフルモード中盤で達成感が得られない。
- **改善案**: 42スキル到達時に「中堅トレーダー」称号 +150,000円 のサブマイルストーンを追加する。または中盤スキル（IND_008 複合指標戦略、RISK_003 SL/TP 併用）完了時の演出を強化する。
- **期待効果**: 中盤の脱落率が下がり、フルコンプリートに向けたモチベーションが持続する。
- **実装難易度**: 低（`skill-data.ts` の `milestones` 配列への1エントリ追加）

### 提案 7: 59スキルコンプリートの特別報酬追加

- **現状**: マスター投資家マイルストーンは 58スキル到達で発動（`skill-data.ts:956`）。最後の 1 スキルを取得しても何の反応もない。`strategy_templates` の unlock が設定されているが、実際の機能が見当たらない。
- **改善案**: 59スキル到達（全コンプリート）に「殿堂入り」演出（フルスクリーンのアニメーション、特別称号「伝説の投資家」、戦略テンプレート解禁）を追加する。`milestones` 配列に `{ skillCount: 59, bonus: 0, title: "伝説の投資家" }` エントリを追加し、専用の達成演出コンポーネントを実装する。
- **期待効果**: 「ラストスキルを取りに行く」モチベーションが生まれ、全体のコンプリート率が向上する。
- **実装難易度**: 中（演出コンポーネントの追加と milestones 定義の修正）

### 提案 8: 各カテゴリ最初のスキルへ helpContent 追加

- **現状**: helpContent が未設定の主要スキル: SANDBOX_006、SETUP_001〜005 全部、DATA_001・004・005・006、SET_001〜003、TRADE_001〜007・009・010、CHART_001〜002、IND_002・004・006〜009、RISK_001〜010 など多数。
- **改善案**: 少なくとも各カテゴリの最初のスキル（SETUP_001, DATA_001, SET_001, TRADE_001, CHART_001, RISK_001）と卒業スキル（SANDBOX_006）には、「このカテゴリで何を学ぶか」のオリエンテーションを含む helpContent を追加する。「ノートブックに挿入」ボタンと組み合わせた体験設計が重要。
- **期待効果**: プレイヤーが迷わず次の操作に進め、脱落ポイントが減少する。
- **実装難易度**: 低（`skill-data.ts` への helpContent 文字列追加のみ）

### 提案 9: SANDBOX_001 helpContent のアクション優先順位明確化

- **現状**: SANDBOX_001「マーケットへようこそ」の helpContent では、「時間を進める」「株を買う」「買注文が決済される」「チャートを見る」の 4 アクションが番号付きで列挙されているが、実際の SANDBOX_001 発火は `bt.chart("7203")` の呼び出しで行われる（`game_setup.py:74`）。プレイヤーはどれを最初に実行すべきか迷う。
- **改善案**: 「最初の 1 アクション: `bt.chart("7203")` を新しいセルで実行してください。このセルを実行すると最初の実績が解除されます」の一行を helpContent の冒頭に追加し、その後のアクションは段階的開示に変更する。
- **期待効果**: 初動の迷いがなくなり、最初の成功体験（チャート表示 = SANDBOX_001 取得）までの時間が短縮される。
- **実装難易度**: 低（helpContent 文字列の編集のみ）

## 詳細分析

### オンボーディング体験の評価

`game_setup.py` が `bt = Backtest_Wrapper(...)` の初期化・データロード・チャート表示をワンラインで提供しており、プレイヤーは `bt.chart("7203")` → `bt.buy()` → `bt.step()` の 3 ステップだけで最初の取引体験ができる設計は秀逸。E2E テストで 9 スキルが自動通過できることが確認されたため、このフローの技術的整合性は高いと評価できる。

ただし `backcast.py` の Markdown セルには操作順序として「bt.step() → bt.buy()」の順が書かれているが、実際の SANDBOX_001 発火は `bt.chart("7203")` の呼び出しで行われる。説明と実装の乖離が初心者の混乱を招く可能性がある。

### スキルツリー設計の評価

**難易度分布**: 難易度 1 が全体の約 57%、難易度 2 が 24%、難易度 3 が 17%、難易度 4 が 2% と、初心者への配慮が見られる。ただし難易度 3 スキル群（IND・RISK の多数）が中盤以降に集中しているため、フルモード移行後の急勾配が課題となる。

**カラーコーディング**: `skill-node.tsx:24-35` の 10 カテゴリ × カラーマッピングは視認性が高く、グラフ上でカテゴリを直感的に識別できる設計として優れている。

**findCurrentTask() の複数 unlocked 時の挙動**: `skill-tree-graph.tsx:23` の `skills.find((s) => s.status === "unlocked")` は配列の先頭から検索するため、並列解放されたスキル（例: SANDBOX_002 完了後に同時 unlocked になる SANDBOX_003 と FAIL_001）において、配列順で最初のスキルにのみフォーカスが当たる。選択肢の存在に気づかせる UI の改善が必要。

### フィードバックループの評価

**スキル取得時**: トースト通知 + スキルツリーダイアログ自動オープンの連携は、「達成 → 確認」の心理的フローに合致している。`_check_graduations()` による自動卒業の「サプライズ感」も良い演出。

**失敗時**: `mo.callout` によるガード警告は設計として正しいが、E2E テストで検出できないことから実際の表示に問題がある可能性がある。失敗体験をゲームデザインとして正面から取り込んでいる点（FAIL スキル群）は優れている。

**進捗感**: `step()` の `_format_step_summary()` で日付・資産・含み損益が整形表示される設計は時間経過の体感に寄与する。HUD の Progress バーもゲームの進行度を示す。
