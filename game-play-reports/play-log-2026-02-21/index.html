    失敗テスト詳細¶

    1. bridge.spec.ts:81 - SANDBOX_006 完了後、BRIDGE_001 が unlocked になる¶

    • エラー: Expected "completed" but received "locked"
    • 原因推定: SANDBOX_001〜006 の連続発火で SANDBOX_006 の完了が propagate される前に BRIDGE_001 のステータスチェックが走っている可能性。タイミング/待機時間の問題。

    2. guard-validation.spec.ts:120 - ポジション保有中に buy() を再度呼ぶと警告メッセージが表示される¶

    • エラー: Expected count 2 but received 1
    • 原因推定: buy() 実行後のスキル発火（SANDBOX_002）が正しくカウントされていない

    3. guard-validation.spec.ts:151 - ポジションなしで sell() を呼ぶと警告メッセージが表示される¶

    • エラー: locator "text=/保有中の株がありません/" not found
    • 原因推定: sell() の警告メッセージテキストが変更されている、またはガード処理が未実装/変更

    4-8. integration.spec.ts (5件) - HTML パイプライン経由テスト¶

    • エラー: 全て Expected "completed" but received "unlocked"
    • 原因推定: __testInjectBroadcastHTML フックが正しく動作していない。HTML注入→BroadcastChannel→リスナー経路の問題
    • 影響テスト:
    • HTML 注入でスキルが完了する
    • 前提条件チェーンが HTML 経由でも動作する
    • 進捗バッジが HTML 経由でも更新される
    • 重複発火が防止される
    • HTML 経由の 6 スキル連続完了でブリッジトラックが解放される

    9. persistence.spec.ts:74 - スキル完了後リロードすると進捗が 0 にリセットされる¶

    • エラー: Expected 0 but received 2
    • 原因推定: リロード後にカーネルがセル出力を再送し、スキルが再発火している（知見35bと関連）
