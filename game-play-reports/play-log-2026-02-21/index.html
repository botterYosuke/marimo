    発見されたバグ・問題¶

    BUG-P1: 再接続時スキルイベント消失（既知、再現確認）¶

    • 症状: ページを再接続（Reconnect）すると、再接続時に発火したスキルイベントが進捗に反映されない（0/59 のまま）
    • 再現手順:
    • marimo server 起動後、backcast.py を開く
    • 既存セッションに Reconnect
    • セルが自動実行され [SkillHandler] Received skill event: SANDBOX_001 がコンソールに出力される
    • スキルツリーを確認すると 0/59 のまま
    • 原因: Jotai atom（非永続化）が新しいブラウザセッションでリセットされるタイミングと、再接続時のスキルイベント受信タイミングがずれる
    • 影響度: P1（ゲームプレイで必ず発生）
    • ステータス: development_docs/game/game-e2e-review-system.md で既知問題として記録済み

    BUG-NEW-1: バックエンドクラッシュ（ValueError: list.remove）¶

    • 症状: ValueError: list.remove(x): x not in list でマリモバックエンドがクラッシュ
    • タイムスタンプ: 2026-02-21 10:59 頃
    • 状況: 複数の WebSocket クライアント（Playwright MCP ブラウザ + E2E テスト）が同時接続中
    • 影響: ゲームセッションが切断、カーネル再起動が必要
    • 再現条件: E2E テスト並列実行中に Playwright MCP ブラウザから window.__testResetProgress() を呼んだ際に発生の可能性
    • ログ: [backend] ValueError: list.remove(x): x not in list

    BUG-NEW-2: ノートブックへのセル蓄積¶

    • 症状: プレイ中に作成した新規セル（cell-7, cell-4の BRIDGE_001 HTML 等）がバックキャスト.py に永続保存される
    • 観察: backcast.py が 7+ セルに増加（本来は 2-3 セル = setup + markdown + chart）
    • 問題: 次回起動時に不要なセルが auto-execute され、スキルが意図せず発火する可能性
    • セル内容:
    • cell-4: 前回テストセッション由来の BRIDGE_001 イベント直接発火コード
    • cell-5: bt.buy() — 前回セッション由来
    • cell-6/7: bt.chart("7203") × 2 — 重複

    BUG-KNOWN-P5: AI Fix バナーがゲームモードで表示される¶

    • 症状: 各セルに「Fix generated / Showing fix / Accept / Reject」バナーが表示される
    • 影響: ゲームプレイの UX を著しく損なう
    • ステータス: 既知問題（development_docs/game/game-e2e-review-system.md の UX プレイテスト P5）
