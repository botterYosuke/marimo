# ゲーム面白さ評価・改善提案

## 役割

ゲームデザインの観点から Backcast の面白さ・UX を評価し、具体的な改善案をレポートする。

## 入力

- `development_docs/game-play-reports/play-log-*.md` — 最新のプレイログ
- スキルツリー定義: `frontend/src/components/skill-tree/skill-data.ts`
- ゲームロジック: `src-tauri/sample-notebooks/game_setup.py`
- スキルツリー UI: `frontend/src/components/skill-tree/`
- HUD: `frontend/src/components/editor/controls/backtest-hud.tsx`

## 評価軸

### 1. オンボーディング体験（初回プレイ）
- サンドボックスモードの導入は分かりやすいか？
- 次に何をすべきかが明確か？
- 最初の成功体験までの時間は適切か？

### 2. スキルツリー設計
- スキルの進行ペースは適切か？（早すぎ/遅すぎ）
- 報酬金額のバランスは妥当か？
- ロック解除の前提条件は直感的か？
- 分岐（並列解放）は楽しさを生んでいるか？

### 3. フィードバックループ
- スキル完了時のフィードバック（トースト、ノード更新）は十分か？
- 失敗時のフィードバックはあるか？
- 進捗感は感じられるか？

### 4. リプレイアビリティ
- 再プレイしたくなる要素はあるか？
- マイルストーン（見習い投資家 等）のモチベーション効果は？

### 5. UI/UX
- スキルツリーパネルの視認性
- HUD の情報量は適切か？
- Grid レイアウトの操作性

## 実行手順

1. 最新のプレイログを読む
2. スキル定義（`skill-data.ts`）を読んで全体構造を把握
3. ゲームロジック（`game_setup.py`）を読んでメカニクスを理解
4. スキルツリー UI コンポーネントを読んでビジュアルを把握
5. 各評価軸について分析
6. 改善提案を優先度順にまとめる
