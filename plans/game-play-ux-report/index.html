    ゲームプレイ UX レポート — 離脱ポイント分析¶

    日時: 2026-02-20 対象: src-tauri/sample-notebooks/backcast.py（サンドボックスモード） 環境: marimo edit (port 2718) + Vite dev server (port 3000) 参考: development_docs/game-e2e-review-system.md

    実施内容¶

    1. backcast.py をmarimo editで起動
    2. チャート表示（bt.chart("7203")）を確認
    3. bt.buy() を入力・実行
    4. bt.step() を入力・実行
    5. スキルツリーダイアログを開いて進捗確認
    6. 各段階でスクリーンショット取得・UI検証

    離脱ポイント一覧（深刻度順）¶

    1. 🔴 スキル完了のフィードバックが無い / 進捗ゼロのまま¶

    深刻度: 致命的

    bt.buy() と bt.step() を実行した後にスキルツリーを開いたところ、0/59 スキルのまま。SANDBOX_001（マーケットへようこそ）すら完了扱いになっていない。

    原因推定: - 既存セッションへの再接続（Reconnected）により、bt.chart("7203") の emit_skill("SANDBOX_001") が発火したタイミングではフロントエンドのスキルツリーリスナーが未接続だった - BroadcastChannel メッセージはリアルタイムのみ送信で、過去の発火は受け取れない

    離脱理由: 「買ったのに何も起きない」「ゲームが壊れている」と感じて閉じる

    改善案: - ページロード時にカーネルから現在の get_triggered_skills() 状態を取得し、フロントエンドと同期する仕組み - または、セル出力再送時にスキルイベントを再発火する

    2. ✅ bt.buy() の出力が意味不明¶

    深刻度: 高 → 対応済み (2026-02-20)

    bt.buy() を実行すると、Outputs パネルに以下が表示されていた:

    <BackcastPro.order.Order object at 0x000001D007657CB0>

    初心者にはこのPythonオブジェクトの repr() は完全に意味不明。「買えたの？ 買えなかったの？ エラー？」と混乱する。

    離脱理由: 「何が起きたかわからない」「エラーっぽい文字列が出た」

    実施した改善:

    game_setup.py の buy() / sell() 関数で mo.output.append(mo.callout(...)) を使い、フレンドリーなメッセージを表示するようにした。

    # buy() — 緑の callout で即座にフィードバック
price = bt._broker_instance.last_price(order.code)
mo.output.append(mo.callout(
    mo.md(f"**買い注文を出しました** — {order.code} @ ¥{price:,.0f}"),
    kind="success",
))

    表示例: 緑の callout「買い注文を出しました — 7203 @ ¥3,138」

    設計判断と背景: - Order.__repr__() の変更ではなく mo.output.append() を採用した理由: - Order クラスは BackcastPro ライブラリ（別リポジトリ）に属しており、ゲーム固有の日本語メッセージを埋め込むのは不適切 - mo.callout は marimo の UI コンポーネントとして色付き（success=緑）で表示され、視認性が高い - repr() は依然として <Order object> だが、callout がその上に表示されるため実質的に目立たない - bt._broker_instance.last_price(order.code) で現在の終値を取得。注文は成行注文（size < 1 は資金比率）のため約定価格は次の step() まで確定しないが、参考価格としてユーザーに提示 - sell() にも同様の改善を適用済み

    変更ファイル: src-tauri/sample-notebooks/game_setup.py (buy: L83-94, sell: L96-110)

    検証: sandbox.spec.ts 10/10 passed

    3. ✅ bt.step() の出力が True のみ¶

    深刻度: 高 → 対応済み (2026-02-20)

    bt.step() を実行すると Outputs に True とだけ表示されていた。

    • 「何日に進んだの？」
    • 「株価は上がった？ 下がった？」
    • 「買い注文は約定した？」

    何の情報もなく、ユーザーは次に何をすべきかわからない。

    離脱理由: 「True って何？」「ゲームが進んでるのかわからない」

    実施した改善:

    game_setup.py に _format_step_summary() ヘルパーを追加し、step() 実行後に情報豊富な callout を表示するようにした。

    # step() が True を返す場合（次の日に進んだ）:
#   青 callout「**2024-01-15** に進みました  株価: ¥3,200 | 資産: **¥102,500** | 含み損益: ¥+2,500」
# step() が False を返す場合（最終日に到達）:
#   緑/赤 callout「**最終日に到達しました！** 最終資産: **¥105,000** | リターン: **+5.0%**」

    設計判断と背景: - result=True（進行中）と result=False（終了）で表示を分岐 - 進行中: 日付・株価・資産額・含み損益を一覧表示（kind="info" 青） - 終了時: 最終資産とリターン%を表示（利益なら kind="success" 緑、損失なら kind="danger" 赤） - 株価は bt._current_data から取得。ポジションがない場合は含み損益を非表示 - 戻り値は True/False のまま変更しない（後方互換性維持）

    変更ファイル: src-tauri/sample-notebooks/game_setup.py (step: L112-125, _format_step_summary: L168-203)

    検証: sandbox.spec.ts 10/10 passed

    4. 🟠 Grid レイアウトのセル重なり¶

    深刻度: 中

    ゲーム起動直後、4つのセルが grid レイアウト上で重なり合っている:

    • cell-1（説明マークダウン）がチャートの上に被さる
    • cell-2（bt.chart("7203")）とcell-3（入力セル）が画面下部で重なる
    • cell-4（AI自動生成の空セル）が中央に浮いている

    離脱理由: 「画面がぐちゃぐちゃで何がどこかわからない」

    改善案: - grid レイアウトの初期配置を改善（セルが重ならないように） - チャートを上半分、説明+入力を下半分に明確に分離

    5. 🟠 AI Fix 提案が全セルに表示される¶

    深刻度: 中

    全てのコードセルに「Fix generated」「Showing fix」「Accept / Reject」バナーが表示されている。これはゲームとは無関係のAIコード修正提案で、ゲーム初心者を大いに混乱させる。

    離脱理由: 「Accept? Reject? 何を承認するの？」「ゲームの一部？」

    改善案: - ゲームモード（backcast テンプレート）では AI Fix を自動非表示にする - または app.setup や metadata でフラグ設定

    6. 🟠 「どこにコードを入力するか」がわからない¶

    深刻度: 中

    説明には「黒いウィンドウに bt.buy() と入力して実行」と書いてあるが:

    • cell-3（意図された入力セル）は画面下端で小さく表示
    • cell-4（AI が生成した空セル）も「黒いウィンドウ」に見える
    • 複数のテキストボックスがあり、どれが「正しい入力場所」か判断できない

    離脱理由: 「どこに書けばいいの？」

    改善案: - 入力セルを目立たせる（ハイライト、矢印アイコン、プレースホルダーテキスト改善） - 「ここに入力 →」のような視覚的ガイド - 不要なセル（cell-4）の自動生成を抑制

    7. 🟡 チャートが step() 後に意味不明な表示になる¶

    深刻度: 低〜中

    bt.step() 実行後、TradingView チャートが大きく変化する: - ローソク足が 1 本しかない極端にズームされた表示 - チャートの大部分が空白 - 「BUY」マーカーは表示されるが、それだけ

    離脱理由: 「チャートが壊れた？」

    改善案: - step() 後のチャート再描画時に適切なズームレベルを維持 - 直近N日分のローソク足が見える範囲にフィット

    8. 🟡 「Reconnected」バナーが意味不明¶

    深刻度: 低〜中

    開発サーバー経由で接続すると「Reconnected: You have reconnected to an existing session.」バナーが表示される。ゲームプレイヤーにとっては意味不明。

    離脱理由: 「何かエラー？ Restartすべき？」

    改善案: - ゲームモードでは自動 dismiss - またはゲーム向けのメッセージに変更（「前回の続きから再開しました」等）

    9. 🟡 ステータスバーが Progress: 0.0% のまま¶

    深刻度: 低

    画面上部のステータスバーに Progress: 0.0% が表示されるが、操作しても変わらない。Time: - も常にハイフンのまま。

    離脱理由: 「操作してるのに何も進んでない」

    改善案: - bt.step() 実行後に Time と Progress を更新 - 視覚的に変化があることを示す（アニメーション等）

    10. 🟡 スキルツリーボタンの存在に気づけない¶

    深刻度: 低

    スキルツリーは右サイドバーの小さなボタン（data-testid="skill-tree-button"）をクリックしないと開かない。ゲームの核心機能であるにも関わらず、発見困難。

    離脱理由: 「このゲームの目標は何？ 進捗はどう確認する？」

    改善案: - 初回プレイ時にスキルツリーを自動表示 - スキル完了時にツリーがポップアップ - ボタンを目立たせる（パルスアニメーション、バッジ通知）

    知見・設計思想・Tips¶

    出力改善のパターン¶

    game_setup.py のラッパー関数で mo.output.append(mo.callout(...)) を使うのが標準パターン。BackcastPro ライブラリ側の __repr__ は変更しない。

    # 標準パターン: ラッパー関数内で callout を追加
def some_action():
    result = bt.some_method()
    mo.output.append(mo.callout(
        mo.md(f"**フレンドリーなメッセージ** — 詳細情報"),
        kind="success",  # success=緑, info=青, warn=黄, danger=赤
    ))
    return result

    callout の kind 使い分け: - "success" (緑): 注文実行など成功アクション（buy, sell） - "info" (青): 状態報告（step の日次サマリー） - "danger" (赤): 損失・破産などネガティブな結果 - "warn" (黄): スキル未解放のゲーティングメッセージ

    bt._broker_instance.last_price(code) について¶

    • 注文時の参考価格として使用。成行注文の実際の約定価格は次の step() で確定するため、あくまで「現在終値」
    • bt._broker_instance はプライベート属性だが、game_setup.py はバックテストエンジンの内部を知る立場（薄いラッパー）なので許容

    _format_step_summary() の分岐¶

    • result=True: 次の営業日に進んだ → 日付・株価・資産・含み損益を表示
    • result=False: 最終日に到達 → 最終資産・トータルリターン%を表示
    • ポジションなし（bt.position.size == 0）の場合は含み損益を非表示にして混乱を避ける

    PyPI バージョン問題¶

    pyproject.toml で BackcastPro>=0.6.4 と指定していたが、PyPI には 0.6.3 までしか公開されていなかった。uv lock がクロスプラットフォーム解決（Python 3.12 on Linux 等）で失敗するため >=0.6.3 に修正。ローカルには editable install で 0.6.4 が入っている。BackcastPro の新バージョンを PyPI に公開したら >=0.6.4 に戻すこと。
